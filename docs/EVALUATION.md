# Evaluation protocol and interpretation

## Verification scope

The two featured pipelines were actually fitted in the recorded Python 3.12 environment using the bundled datasets. Their current tables, figures, environment records, and row-split files were generated by these runs. Decision tests and repository integrity checks are separate from full training; CI runs the lightweight checks without claiming to repeat model fitting.

The original bank report and source snapshots predate this refactor. Original notebook saved outputs are not silently reused as newly reproduced results. All feature transformations are fitted through separate estimator pipelines, and bank calibration wraps the complete preprocessing/model pipeline.

## Bank marketing

- Dataset: 41,188 historical contact records, 19 classifier features; `duration` and `y` excluded from the classifier.
- Split: seeded, stratified 60/20/20 random row split. The row IDs are retained in `projects/bank-marketing/results/row_splits.csv.gz`.
- Model selection: minimum validation Brier score for classification; minimum validation RMSE for expected-duration forecasting. The originally studied log-duration forest is also retained as an explicit experimental comparison.
- Calibration: three-fold sigmoid calibration with preprocessing refitted inside each fold.
- Decision rule: stable descending score order; select the prefix whose cumulative predicted minutes are at most the chosen forecast budget. For duration-aware ranking, candidates with nonpositive projected profit are excluded. This is not a knapsack solver.
- Buffer: select separately for each scenario, duration model, and policy from `[0.6,0.7,0.8,0.9,1.0]`, using validation simulated profit subject to actual validation time. If none are feasible, the code falls back to no contacts. A validation-feasible buffer does not guarantee test feasibility.
- Test scoring: actual outcomes and call durations are passed only to evaluation. Forecast and actual budget flags are separate.
- Economics: baseline `(revenue=100, fixed cost=1, cost/minute=4, budget=3000)`; stress `(100,1,1,1500)`. Changing both variable cost and budget prevents attributing differences exclusively to budget tightening.

Financial values are hypothetical monetary units. Historical positive subscription labels are not incremental effects caused by contact. A useful future extension is an out-of-time campaign evaluation with duration calibration and uncertainty-aware capacity rules.

## Donor targeting and routing

- Data: 27,132 source training rows, 18,090 source test rows. Stage-two training uses 13,566 known, labeled source training rows.
- Model selection: each stage has a stratified 80/20 internal split of its applicable training data. Models are selected by validation AUC and refitted on that stage's source training rows.
- Routing features: latitude, longitude, contact status, and model scores; observed future-donation labels are excluded from route selection.
- Hybrid: inherited known/cold switching rule. Its rationale was informed by the original course test analysis, so this same file is not an untouched validation of that rule.
- Threshold: choose from `.05,.10,...,.50` by projected net using scores and distances only. The same threshold is held fixed across distance-budget sensitivity runs.
- Route: nearest feasible candidate among the allowed subset, with deterministic tie handling and enough distance reserved for a depot return. The route starts and ends at depot zero and never visits a candidate twice.
- Distance: Haversine with Earth radius 6,371.0088 km. This differs slightly from the original geodesic helper and does not model roads, traffic, or visit time.
- Economics: 200 units per donation, 5 per visit, 10 per kilometer.

Income scores cannot be treated as calibrated donation probabilities. The schema therefore distinguishes `score_based_projected_net` from `historical_simulated_net`. The route comparison is a single fixed sample of 200 candidates, without confidence intervals or a route optimality guarantee. A practical next study would use representative response labels, probability calibration, repeated candidate samples, and a separate future population.

## Retrospective limits

Both source test sets had already been examined in coursework. Refitting models using a cleaner internal validation procedure improves the mechanics but does not erase that history. The current results describe reproducible retrospective case studies. No causal impact, production readiness, future-campaign performance, or guaranteed budget compliance is claimed.
